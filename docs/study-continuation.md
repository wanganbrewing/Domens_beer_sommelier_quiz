# 連続学習と直近正答率

## 操作

全問の回答を確認したら、最後の解説下に「結果を見る」を表示する。結果画面の上部に「次の50問へ」「終わる」を配置し、同じ問題への再挑戦と各問の復習も残す。問題一覧から飛ばして最後の問題を解いた場合は「未回答へ」で未確認の問題へ戻る。

- 次のセットも、最初に選んだ分野・頻度・履歴条件を使用する。履歴条件の判定はその時点の最新履歴に基づく。
- 「次の問題へ」で続けた間の既出IDを保存し、残っている対象問題だけを出す。50問未満なら「次の23問へ」のように実数を表示する。全て出したら次ボタンを無効にし、終了を案内する。重複で50問へ水増ししない。
- 結果画面も途中の回も再読み込みで復旧する。再挑戦は同じIDを使い、連続学習の既出一覧を保つ。通常の学習をホームから新たに始めた場合は新しい連続学習として扱う。
- 既存の学習保存データには条件・連続学習IDがないため、最初の継続時に保存済みホーム条件を使用し、現在の回から既出IDを記録する。旧最終試験の学習への復旧も維持する。
- 8問の別セット専用学習は、その8問の再挑戦と終了を案内する。通常の50問へ自動的に混ぜない。
- 模試は新しい連続学習操作の対象外。既存の50問、40分期限、採点、合否、同じ問題への再挑戦を維持する。

## 履歴と直近正答率

既存の問題別履歴・累計回答・正解済み件数はそのまま保持する。学習の回答確定と模試の採点時に、その回答の完全正解／不正解を専用の最大50件の記録へ追加する。問題IDの重複を除いた50問ではなく、再挑戦も含めた直近50回答である。

ホームでは「直近正答率」として完全正解数÷対象回答数を表示し、「直近N回答・完全正解M問」を併記する。少数回答時も分母に実件数を使う。部分点は完全正解に数えない。模試の未回答は不正解として含める。模試50問は提出／時間切れの採点時に1回分まとめて記録する。

旧履歴には全回答の時系列がないため、新しい直近集計を過去の累計から推測しない。新たな回答がない間は「—」と案内を表示する。学習履歴削除時は直近集計も削除する。

直近正答率に合格判定は付けない。模試は正しい選択肢の加点・誤選択の減点を用いた得点率50%以上で合格。50%ちょうどを含む。

## 検証

- 統合版では既存14検査、日本語併記1検査、連続学習・直近正答率2検査の計17検査を実行。
- `validate_study_continuation.js`: 選択肢エンジン有無の双方で50→50→23問の全123問を重複なく出題、枯渇、条件保存、履歴条件、飛ばした未回答、二重クリック、結果・途中の再読み込み、再挑戦・キャンセル、旧保存データ、専用8問・模試との分離、履歴の二重記録なし。
- `validate_recent_accuracy.js`: 旧累計履歴の保持、1・2・50回答、直近50件の入れ替え、再読み込み、削除・キャンセル、部分点と完全正解の区別、二重採点なし。模試49%不合格／50%合格／51%合格。
- 文言修正検査の「UIをバイト単位で完全固定」する条件は、既存認証・保存キー・採点・出題配分・タイマーの保持検査と上記の機能回帰検査へ変更。このUI変更では問題データ・写真類は不変。統合版では別途、正誤を変えない日本語併記を適用。
- `node --check app.js`、`git diff --check` を実行。

### 実画面検証の制約

この作業環境ではChromiumが `socket() failed: Operation not permitted` で起動せず、用意されたブラウザーからもローカルプレビューへ接続できなかった。自動検査は通過したが、スマホ幅・デスクトップ幅の実ブラウザー描画は未検証。公開URLへの反映後に、最後の解説→結果→次セット、結果の再読み込み、終了、直近カードの折り返しを追加確認する。iPhone実機の確認とは区別する。
